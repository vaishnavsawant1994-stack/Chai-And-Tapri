# CAT-051B SAF clean-install recovery drill — 26 November 2026

## Result

The current-source encrypted backup UI and restore flow passed on the dedicated `Tapri_Recovery_Clean_2026` API 37 AVD. The test created only synthetic business data, exported a `.ctbackup` file through Android's CreateDocument UI to shared Downloads, let the test runner remove the app package, then installed a fresh app package and restored the archive through Android's OpenDocument UI. The archive remained outside app-private storage across that fresh install. The restored database opened with the new app installation's local key provisioning and preserved the archive data.

The clean-install assertions verified two orders, cash collected, pending UPI kept pending, refunded value and credit reversal, outstanding customer credit, repayment history, stock balances/movements, audit history, and that retrying the same command did not create another sale. Table reconciliation checked command receipts against outbox rows, audit event counts, and payment ledger counts.

## Rejected-key behavior

An initial attempt selected the rich synthetic archive while using the different recovery secret expected by the SAF test fixture. The UI displayed `Backup verification failed; active data was not changed: Backup header authentication failed.` No replacement was offered or performed. This was a test-input mismatch, not an archive corruption; the correct archive generated by the UI then passed. `pm clear` was attempted after the test-runner had already uninstalled the app and returned `Failed`; package enumeration confirmed no target app package/data was present before the fresh-install test.
